# 2026-11-01

## STGR Browser — initial build (v0.1.0 scaffold)

Built the full repository for a Windows-only Chromium distribution named STGR Browser,
branded from `~/Downloads/logo.png`, targeting the supplied UI mockup.

**Architecture decision that governs everything:** GitHub-hosted runners cannot compile
Chromium (~100 GB disk / 32 cores needed vs 14 GB / 4 cores available). So Stage 1 is a
*distribution* build — pinned upstream Chromium snapshot + our branding/defaults/extensions
+ NSIS installer. Stage 2 (source fork with patches) is scaffolded for a self-hosted runner.
Recorded in `docs/decisions/ADR-0002-build-strategy.md`.

**Key files**
- `branding/brand.json` — single source of truth (name, IDs, colours, speed dial)
- `branding/generate-icons.py` — PNG set + multi-size ICO + ICNS, hand-rolled containers
- `ntp/` — New Tab Page as an MV3 extension; background is hand-built SVG (torii + 5-tier
  pagoda), no external assets
- `extensions/stgr-shield` — hosts lists compiled to declarativeNetRequest at build time
- `scripts/build.py` — fetch → assemble → C# launcher → makensis
- `overrides/windows/installer.nsi` — per-user NSIS installer, no UAC
- `AGENTS.md` + `docs/AGENT-STATE.md` — handoff contract for successor agents

**Non-obvious things learned**
- `initial_preferences` (next to the exe) is the only supported way to seed a fresh profile;
  it does nothing for an existing one. This is the #1 debugging trap.
- Chromium keeps only one `--disable-features` switch; duplicates are silently dropped.
  `build.py` merges `@include` chains and feature lists to avoid this.
- Per-user policies must go to `HKCU\Software\Policies\Chromium`, not a product-named key,
  because the binary is upstream Chromium.
- An MV3 theme is the only way to recolour Chromium chrome without a source build.

**Status:** never executed in CI. First push is the first real test.

**UI notes:** mockup showed "Firefox Gecko Engine" and "uBlock Origin" — replaced with
Chromium and STGR Shield, since the brief is a Chromium browser.
