# STGR Build Branding Directory

This directory is the repository source for the STGR branding files. Before
configure, `scripts/build_stgr.py prepare` copies these files and generated
icons into `firefox/browser/branding/stgr`, the in-tree directory passed to
`--with-branding`. Firefox's branding machinery reads the staged copy.

## Contents

| File | Purpose |
|---|---|
| `brand.ftl` / `brand.dtd` / `brand.properties` | Product name strings |
| `configure.sh` | Product display name consumed by Firefox's branding configure contract |
| `moz.build` | Registers the staged branding resources with Firefox's build system. Mirrors `browser/branding/nightly/moz.build`: sets `DIST_SUBDIR = "browser"` and invokes the `FirefoxBranding()` template from `../branding-common.mozbuild` so `mach package` finds the VisualElements tiles, Start-tile manifests, and `pref/firefox-branding.js` at the exact paths `browser/installer/package-manifest.in` expects |
| `branding.nsi` | STGR product/company/installer definitions for the Windows NSIS build |
| `firefox.VisualElementsManifest.xml` / `private_browsing.VisualElementsManifest.xml` | Windows Start-tile manifests (installed to `bin/`) |
| `VisualElements_{150,70}.png` / `PrivateBrowsing_{150,70}.png` | Windows Start-tile logos (installed to `bin/browser/VisualElements/`) — **generated** by downscaling the master `stgr/branding/icons/icon-512.png` |
| `pref/firefox-branding.js` | Branding preferences (installed to `bin/browser/defaults/preferences/` via the `FirefoxBranding()` template's `JS_PREFERENCE_FILES`) |
| `locales/moz.build` + `locales/jar.mn` + `locales/en-US/brand.{ftl,properties}` | Langpack support. `moz.build` (declared via `DIRS` in the top-level `moz.build`) makes the backend generate `browser/branding/stgr/locales/Makefile`, which the en-US langpack build requires (`browser/locales/Makefile.in` `SUBMAKEFILES`); `jar.mn` packs the brand strings into the localization jar. Without this directory `mach package` dies with `No rule to make target '../../browser/branding/stgr/locales/Makefile'` |
| `stubinstaller/*.css` | STGR styling for Firefox's Windows installer pages |
| `firefox.ico` + `default{16,32,48,64,128,256,512}.png` | Application icons — **generated** by `scripts/make_icons.py` from the master logo (`stgr/branding/stgr-logo.png`), staged by `build_stgr.py prepare` |
| `wizHeader*.bmp`, `wizWatermark.bmp`, `stubinstaller/bgstub.jpg` | STGR-owned NSIS artwork generated by `scripts/make_installer_assets.py` during prepare |

The icon files and Start-tile PNGs are derived assets and are committed so CI
builds do not require Pillow/cairosvg. Installer artwork is generated during
`prepare` with the Python standard library. No Mozilla installer artwork or
certificate identity is copied.
Until the official logo is provided, `python scripts/make_icons.py --generate-placeholder`
creates test-only stand-ins.

## App identity notes

- Firefox's `browser/moz.configure` supplies the upstream application ID
  (`{ec8030f7-c20a-464f-9b0e-13a3a9e97384}`), preserving WebExtension
  `applications.gecko.id` compatibility. The branding script must not override
  that implied option.
- Firefox's modern Windows build configuration owns executable and profile
  identity. STGR-specific product naming is supplied through the display name,
  brand strings, About page, and distribution assets.
